### 3.0.1 TOS 系统两个关键坑（复用价值高）

| 坑 | 现象 | 根因 | 解法 |
| -- | ---- | ---- | ---- |
| tmacl 文件拦截 | systemd 服务进程读 `/Volume1` 下文件报 `permission denied`（SSH 会话 root 读取正常） | `/Volume1` 挂载带 `tmacl`（TOS 专有 ACL），SSH 登录会话持有 TMACL 上下文而服务进程没有 | 生产配置迁移至 `/etc/frp/frpc.toml`（chmod 600），日志迁移至 `/var/log/frpc/` |
| PID 1 子进程出站拦截 | 裸 frpc（父进程=systemd）`connect` 报 `permission denied`；手工或 `timeout` 包裹的同一进程正常 | TOS 应用管控按父子进程特征拦截（非 iptables/nftables，规则集为空） | unit 的 `ExecStart` 使用 `/usr/bin/timeout 0` 包装：`ExecStart=/usr/bin/timeout 0 /Volume1/www/frpc/frpc -c /etc/frp/frpc.toml` |

> 排障方法沉淀：`systemd-run --pipe --wait` 临时单元做对照实验区分"上下文差异"与"时间窗/动态封禁"；iptables/nft 全量规则排除常规防火墙后，剩余变量即父子进程链。

### 3.3 轮换 JWT 签发密钥（如有生产 API）

```bash
# 生成新密钥
python3 -c "import secrets; print(secrets.token_urlsafe(48))"

# 更新生产 env（按部署文档 config/secrets/*.env 路径）后重启 API 服务
# 注意：更换 JWT 密钥会使所有已签发 token 失效，用户需重新登录
```

部署文档中的 `ALIYUN_ACCESS_KEY_ID/SECRET` 虽为占位符，若生产曾使用与文档示例相近的值，建议一并在阿里云控制台轮换。
