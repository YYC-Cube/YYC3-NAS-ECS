## 三、生产环境必须执行的步骤（P0）

### 3.1 更新服务端凭据并重启 frps

```bash
# 1. 同步新凭据到生产服务器（scp 或密码管理器分发）
scp config/secrets/frp.env prod@nas:/etc/yyc3/secrets/frp.env

# 2. 在生产服务器上加载环境变量后启动 frps
set -a; source /etc/yyc3/secrets/frp.env; set +a
systemctl restart frps   # 或按现有部署方式重启

# 3. 验证 token 生效（旧 token 连接应被拒绝）
grep "FRP_AUTH_TOKEN" /etc/yyc3/secrets/frp.env  # 确认新值
```

### 3.2 更新所有 frpc 客户端 token

```bash
# 每台运行 frpc 的机器上更新 auth.token 为新值后重启
systemctl restart frpc
```

### 3.3 轮换 JWT 签发密钥（如有生产 API）

```bash
# 生成新密钥
python3 -c "import secrets; print(secrets.token_urlsafe(48))"

# 更新生产 env（按部署文档 config/secrets/*.env 路径）后重启 API 服务
# 注意：更换 JWT 密钥会使所有已签发 token 失效，用户需重新登录
```

### 3.4 阿里云 AccessKey（建议）

部署文档中的 `ALIYUN_ACCESS_KEY_ID/SECRET` 虽为占位符，若生产曾使用与文档示例相近的值，建议一并在阿里云控制台轮换。

## 四、git 历史清理（可选，P2）

泄漏值已从当前 HEAD 移除，但 git 历史中仍可追溯。如仓库为公开或需彻底清除：

```bash
# 使用 git-filter-repo 全历史替换泄漏值（会重写历史，需团队协调 + force push）
pip install git-filter-repo
git filter-repo --replace-text <(echo "yyc3_nas==>REDACTED")
git filter-repo --replace-text <(echo "my151001==>REDACTED")
```

> 由于服务端已轮换新 token，历史中的旧值已无实际危害，历史清理为可选加固项。
