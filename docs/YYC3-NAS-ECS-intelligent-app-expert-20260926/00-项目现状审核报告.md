## 三、关键发现（按严重程度分级）

### 🔴 P0 - 阻断性问题（必须立即修复，否则无法发布）

#### P0-1: 生产构建失败 — 缺失模块导入

**位置**: `src/App.tsx:3, 15`

**问题**: App.tsx 导入了两个不存在的模块，导致 `vite build` 失败。

```typescript
// src/App.tsx 第 3 行 — 模块不存在
import { AIWidgetProvider, IntelligentAIWidgetWrapper } from './app/lib/ai-integration';

// src/App.tsx 第 15 行 — 模块不存在
import { LogViewer } from './app/components/logs/LogViewer';
```

**实测结果**:

```
✗ Build failed in 476ms
error during build: Could not resolve "./app/lib/ai-integration" from "src/App.tsx"
```

**根因分析**:

- `src/app/lib/` 目录完全不存在。`AIWidgetProvider` 实际定义在 `src/components/ai-floating-widget/AIWidgetProvider.tsx`，但 `IntelligentAIWidgetWrapper` 在整个 `src/` 中无定义（仅有 `IntelligentAIWidget`）。
- `src/app/components/logs/` 目录不存在，`LogViewer` 组件未实现。
- 这属于**重构后未清理导入**或**合并冲突未解决**导致的断链。

**影响**: 应用完全无法构建发布，CI/CD 构建阶段会失败。

**修复方案**:

1. 修正 `AIWidgetProvider` 导入路径为 `../components/ai-floating-widget`
2. 为 `IntelligentAIWidgetWrapper` 创建包装组件，或替换为已有的 `IntelligentAIWidget`
3. 实现 `LogViewer` 组件（参考 `logService.ts`）或移除该路由

---

#### P0-2: 1276 个 TypeScript 编译错误

**位置**: `src/` (53 个) + `services/ai/` (1223 个)

**问题**: `tsc --noEmit` 报告 1276 个错误，CI 中的 `type-check` 任务会失败。

**错误分布**:

| 区域          | 错误数 | 主要错误类型                                   |
| ------------- | ------ | ---------------------------------------------- |
| `src/`        | 53     | 缺失模块导入、类型不匹配、隐式 any             |
| `services/ai/`| 1223   | 缺失依赖(uuid)、未使用变量、缺失类型定义       |

**src/ 典型错误**:

- `src/app/components/DocQualityDashboard.tsx`: 无法解析 `@/components/ui/card` 等路径别名
- `src/app/components/api/APIModule.tsx`: API 响应类型与实际类型不匹配（`success`/`data` 属性不存在）
- `src/app/config/env.ts`: boolean 与 string 比较错误（环境变量类型处理不当）
- `src/app/services/api-v2.ts`: `MockDataService` 与 `ApiService` 接口不兼容
- `src/EmailApp.tsx`: `ModuleTheme` 未从 ThemeContext 导出

**services/ai/ 典型错误**:

- `core/ai/AgentManager.ts`: 无法找到模块 `uuid`
- 大量 `TS6133` 未使用变量/参数（`noUnusedLocals` 启用）
- `core/industries/IndustryAdapter.ts`: 缺失类型 `IndustryConfiguration`

**根因分析**:

1. 根 `tsconfig.json` 的 `include: ["src", "services"]` 将 `services/ai` 纳入编译，但 `services/ai` 有独立的 `tsconfig.json`，且其依赖（如 `uuid`）未安装
2. 类型定义与 API 响应实际结构不同步（mock 数据与真实接口类型漂移）
3. 环境变量统一按 string 读取，但代码中按 boolean 比较

**影响**:

- CI `type-check` 任务失败
- 类型安全名存实亡，运行时错误风险高
- IDE 开发体验差

**修复方案（分阶段）**:

1. **立即**: 根 `tsconfig.json` 排除 `services/`（`services/ai` 用自己的 tsconfig 独立检查），或将 `services/ai` 移出根编译范围
2. **短期**: 修复 `src/` 中 53 个错误（路径别名、类型对齐）
3. **中期**: 为 `services/ai` 安装缺失依赖，系统性修复 674 个错误

#### P0-3: JWT 密钥弱默认值

**位置**: `api/config/config.py:11`

**问题**: JWT 签名密钥使用弱默认值，若环境变量未设置则使用已知弱密钥。

```python
JWT_SECRET_KEY = os.environ.get('JWT_SECRET_KEY') or 'jwt-secret-key-change-me'
SECRET_KEY = os.environ.get('SECRET_KEY') or 'dev-secret-key-please-change'
```

**根因**: 开发便捷性优先于安全，缺少生产环境启动时的强制校验。

**影响**: 攻击者可使用已知密钥伪造任意用户的 JWT token，完全绕过认证。

**修复方案**:

```python
# 生产环境强制要求环境变量，否则启动失败
if os.environ.get('ENVIRONMENT') == 'production':
    if not os.environ.get('JWT_SECRET_KEY'):
        raise RuntimeError('JWT_SECRET_KEY must be set in production')
    if len(os.environ['JWT_SECRET_KEY']) < 32:
        raise RuntimeError('JWT_SECRET_KEY must be at least 32 characters')
```

### 🟠 P1 - 高优先级问题（影响安全/稳定性，应尽快修复）

#### P1-1: CORS 策略默认为通配符 `*`

**位置**: `api/config/config.py:48`, `api/docker-compose.yml`

```python
CORS_ORIGINS = os.environ.get('CORS_ORIGINS', '*')
```

**问题**: 默认允许任意来源跨域访问，生产环境若未配置 `CORS_ORIGINS` 环境变量，则全站开放 CORS。

**影响**: 恶意网站可发起跨域请求窃取用户数据（配合 JWT 风险）。

**修复方案**: 生产环境默认值改为具体域名列表，并在启动时校验。

#### P1-2: 前端 VITE_ 前缀暴露 JWT 密钥到客户端

**位置**: `.env.production` (`VITE_AUTH_JWT_SECRET`), `src/app/services/configService.ts:160`

**问题**: `VITE_` 前缀的环境变量会被 Vite 打包进客户端 JS bundle，任何用户都可从浏览器中提取。

```typescript
// configService.ts 校验 JWT 密钥长度 — 说明该值在客户端可见
if (config['VITE_AUTH_JWT_SECRET'] && config['VITE_AUTH_JWT_SECRET'].length < 32) {
```

**影响**: 若该密钥与后端 `JWT_SECRET_KEY` 一致，则客户端可伪造 token。

**修复方案**:

1. 确认 `VITE_AUTH_JWT_SECRET` 是否实际用于 JWT 签名/验证（当前代码中未发现前端 JWT 签名，仅用于配置校验）
2. 重命名为非敏感用途（如 `VITE_AUTH_SECRET_MIN_LENGTH`）或移至后端校验
3. 后端密钥绝不能以 `VITE_` 前缀出现在前端

## 四、问题分析（根本原因定位）

### 4.1 构建失败根因链

```
重构/合并 → 导入路径未同步更新 → App.tsx 引用不存在的模块
                                ↓
                        vite build 失败
                                ↓
                    CI 构建任务失败 → 无法发布
```

**根因**: 缺少**构建门禁**。虽然 CI 定义了 build 步骤，但本地开发流程中没有强制的 pre-commit 构建检查，导致断链代码被提交。

### 4.2 类型错误泛滥根因

```
tsconfig.json include 范围过大 (src + services)
        ↓
services/ai 有独立 tsconfig 但被根 tsconfig 重复编译
        ↓
services/ai 依赖未安装 + 类型定义缺失
        ↓
1223 个错误污染整体类型检查
```

**根因**: Monorepo 边界不清。根项目与 `services/ai` 的 TypeScript 工程边界未通过 project references 正确隔离。

### 4.3 安全配置弱化根因

```
开发优先 → 默认值设为弱密钥/通配符 CORS
        ↓
生产环境未强制校验环境变量
        ↓
弱默认值可被意外启用
```

**根因**: 缺少**生产环境启动守卫**。`env_validator.py` 存在但未在生产启动流程中强制执行。
