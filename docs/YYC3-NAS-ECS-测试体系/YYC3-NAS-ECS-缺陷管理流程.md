## 🏷️ 缺陷分类

### 严重级别

#### 1. 严重（Critical）

**定义**：系统崩溃、数据丢失、安全漏洞等严重影响系统稳定性和安全性的缺陷。

**示例**：
- 系统无法启动
- 数据库连接失败
- 用户数据丢失
- 安全漏洞（SQL注入、XSS攻击等）
- 支付功能异常

**响应时间**：立即响应，24小时内修复

**责任人**：开发负责人

#### 2. 高（High）

**定义**：主要功能无法使用、严重影响用户体验的缺陷。

**示例**：
- 核心功能无法使用
- 严重的UI/UX问题
- 性能严重下降
- 兼容性问题

**响应时间**：4小时内响应，48小时内修复

**责任人**：开发工程师

#### 3. 中（Medium）

**定义**：次要功能异常、轻微影响用户体验的缺陷。

**示例**：
- 次要功能无法使用
- 轻微的UI/UX问题
- 性能轻微下降
- 非关键路径的错误

**响应时间**：8小时内响应，72小时内修复

**责任人**：开发工程师

#### 4. 低（Low）

**定义**：不影响功能使用、不影响用户体验的缺陷。

**示例**：
- 文档错误
- 轻微的样式问题
- 非关键路径的警告
- 建议性改进

**响应时间**：24小时内响应，7天内修复

**责任人**：开发工程师

#### 5. 微（Trivial）

**定义**：不影响功能使用、不影响用户体验的微小问题。

**示例**：
- 拼写错误
- 格式问题
- 不影响使用的建议

**响应时间**：48小时内响应，下次版本修复

**责任人**：开发工程师

### 缺陷类型

#### 1. 功能缺陷

**定义**：功能实现与需求规格不符的缺陷。

**示例**：
- 功能缺失
- 功能错误
- 功能不完整
- 功能不符合需求

#### 2. 性能缺陷

**定义**：系统性能不符合要求的缺陷。

**示例**：
- 响应时间过长
- 内存占用过高
- CPU占用过高
- 并发处理能力不足

#### 3. 兼容性缺陷

**定义**：系统在不同环境下的兼容性问题。

**示例**：
- 浏览器兼容性问题
- 操作系统兼容性问题
- 设备兼容性问题
- 版本兼容性问题

#### 4. 安全缺陷

**定义**：系统安全漏洞和安全隐患。

**示例**：
- SQL注入漏洞
- XSS攻击漏洞
- CSRF攻击漏洞
- 权限控制漏洞

#### 5. UI/UX缺陷

**定义**：用户界面和用户体验问题。

**示例**：
- 界面布局问题
- 交互体验问题
- 样式问题
- 可访问性问题

#### 6. 数据缺陷

**定义**：数据处理和存储问题。

**示例**：
- 数据丢失
- 数据错误
- 数据不一致
- 数据存储问题

#### 7. 文档缺陷

**定义**：文档和说明问题。

**示例**：
- 文档错误
- 文档缺失
- 文档不完整
- 文档不准确

## 🔄 缺陷生命周期

### 状态定义

#### 1. 新建（New）

**定义**：缺陷刚被发现，尚未被确认。

**触发条件**：
- 测试人员发现缺陷
- 用户报告缺陷
- 开发人员发现缺陷

**下一步**：待确认

#### 2. 待确认（Confirmed）

**定义**：缺陷已被确认，等待分配。

**触发条件**：
- 测试人员确认缺陷
- 产品经理确认缺陷
- 技术负责人确认缺陷

**下一步**：待修复

#### 3. 待修复（Assigned）

**定义**：缺陷已分配给开发人员，等待修复。

**触发条件**：
- 缺陷已分配给开发人员
- 开发人员已接受缺陷

**下一步**：修复中

#### 4. 修复中（In Progress）

**定义**：开发人员正在修复缺陷。

**触发条件**：
- 开发人员开始修复缺陷
- 开发人员正在分析缺陷

**下一步**：待验证

#### 5. 待验证（Fixed）

**定义**：缺陷已修复，等待测试验证。

**触发条件**：
- 开发人员已完成修复
- 代码已提交到版本控制

**下一步**：已验证或重新打开

#### 6. 已验证（Verified）

**定义**：缺陷已修复并通过测试验证。

**触发条件**：
- 测试人员验证通过
- 缺陷修复符合要求

**下一步**：已关闭

#### 7. 重新打开（Reopened）

**定义**：缺陷修复后测试未通过，需要重新修复。

**触发条件**：
- 测试人员验证失败
- 缺陷修复不符合要求

**下一步**：待修复

#### 8. 已关闭（Closed）

**定义**：缺陷已修复并验证通过，可以关闭。

**触发条件**：
- 缺陷已验证通过
- 缺陷修复符合要求

**下一步**：无

#### 9. 已拒绝（Rejected）

**定义**：缺陷被拒绝，不是真正的缺陷。

**触发条件**：
- 产品经理拒绝缺陷
- 技术负责人拒绝缺陷
- 缺陷不是真正的缺陷

**下一步**：已关闭

#### 10. 已延期（Deferred）

**定义**：缺陷被延期到后续版本修复。

**触发条件**：
- 产品经理决定延期
- 技术负责人决定延期
- 缺陷不影响当前版本

**下一步**：待修复（后续版本）

### 状态流转图

```
新建 → 待确认 → 待修复 → 修复中 → 待验证 → 已验证 → 已关闭
                                    ↓
                               重新打开
                                    ↑
                              待修复 → 已延期 → 已关闭
                                    ↑
                              待确认 → 已拒绝 → 已关闭
```

#### 3. 自定义跟踪系统

**用途**：缺陷跟踪和统计分析

**配置**：

```typescript
interface Defect {
  id: string;
  title: string;
  severity: 'critical' | 'high' | 'medium' | 'low' | 'trivial';
  type: 'functional' | 'performance' | 'compatibility' | 'security' | 'ui-ux' | 'data' | 'documentation';
  priority: 'P1' | 'P2' | 'P3' | 'P4' | 'P5';
  status: 'new' | 'confirmed' | 'assigned' | 'in-progress' | 'fixed' | 'verified' | 'reopened' | 'closed' | 'rejected' | 'deferred';
  reporter: string;
  reportedAt: Date;
  assignee: string;
  module: string;
  version: string;
  description: string;
  steps: string[];
  expected: string;
  actual: string;
  environment: string;
  attachments: string[];
  rootCause?: string;
  fixSuggestion?: string;
  impactScope?: string;
  relatedRequirements?: string[];
  relatedDefects?: string[];
  notes?: string;
}

class DefectTracker {
  private defects: Map<string, Defect> = new Map();

  createDefect(defect: Omit<Defect, 'id' | 'reportedAt'>): Defect {
    const id = this.generateDefectId();
    const newDefect: Defect = {
      ...defect,
      id,
      reportedAt: new Date()
    };
    this.defects.set(id, newDefect);
    return newDefect;
  }

  updateDefect(id: string, updates: Partial<Defect>): Defect | null {
    const defect = this.defects.get(id);
    if (!defect) return null;
    const updatedDefect = { ...defect, ...updates };
    this.defects.set(id, updatedDefect);
    return updatedDefect;
  }

  getDefect(id: string): Defect | null {
    return this.defects.get(id) || null;
  }

  listDefects(filter?: Partial<Defect>): Defect[] {
    const defects = Array.from(this.defects.values());
    if (!filter) return defects;
    return defects.filter(defect => {
      return Object.entries(filter).every(([key, value]) => {
        return defect[key as keyof Defect] === value;
      });
    });
  }

  deleteDefect(id: string): boolean {
    return this.defects.delete(id);
  }

  private generateDefectId(): string {
    const year = new Date().getFullYear();
    const count = this.defects.size + 1;
    return `BUG-${year}-${String(count).padStart(4, '0')}`;
  }
}

export const defectTracker = new DefectTracker();
```

**使用**：

```typescript
// 创建缺陷
const defect = defectTracker.createDefect({
  title: '用户登录失败',
  severity: 'high',
  type: 'functional',
  priority: 'P1',
  status: 'new',
  reporter: '张三',
  assignee: '李四',
  module: '用户认证',
  version: 'v1.0.0',
  description: '用户输入正确的用户名和密码后，点击登录按钮，系统提示"用户名或密码错误"',
  steps: [
    '打开登录页面',
    '输入用户名"admin"',
    '输入密码"password"',
    '点击登录按钮'
  ],
  expected: '登录成功，跳转到首页',
  actual: '登录失败，提示"用户名或密码错误"',
  environment: 'macOS 14.0, Chrome 120.0, MacBook Pro M2',
  attachments: []
});

// 更新缺陷
defectTracker.updateDefect(defect.id, { status: 'confirmed' });

// 查询缺陷
const defects = defectTracker.listDefects({ status: 'new' });

// 删除缺陷
defectTracker.deleteDefect(defect.id);
```

### 跟踪指标

#### 1. 缺陷数量

| 指标 | 说明 | 计算公式 | 目标值 |
|------|------|---------|--------|
| 总缺陷数 | 所有缺陷数量 | COUNT(所有缺陷) | - |
| 新增缺陷数 | 新增缺陷数量 | COUNT(新增缺陷) | - |
| 已修复缺陷数 | 已修复缺陷数量 | COUNT(已修复缺陷) | - |
| 未修复缺陷数 | 未修复缺陷数量 | COUNT(未修复缺陷) | <10 |

#### 2. 缺陷分布

| 指标 | 说明 | 计算公式 | 目标值 |
|------|------|---------|--------|
| 严重缺陷占比 | 严重缺陷占比 | COUNT(严重缺陷) / COUNT(所有缺陷) | <5% |
| 高缺陷占比 | 高缺陷占比 | COUNT(高缺陷) / COUNT(所有缺陷) | <10% |
| 中缺陷占比 | 中缺陷占比 | COUNT(中缺陷) / COUNT(所有缺陷) | <20% |
| 低缺陷占比 | 低缺陷占比 | COUNT(低缺陷) / COUNT(所有缺陷) | <40% |
| 微缺陷占比 | 微缺陷占比 | COUNT(微缺陷) / COUNT(所有缺陷) | <25% |

#### 3. 缺陷趋势

| 指标 | 说明 | 计算公式 | 目标值 |
|------|------|---------|--------|
| 缺陷增长率 | 缺陷增长率 | (本周新增缺陷 - 上周新增缺陷) / 上周新增缺陷 | <0 |
| 缺陷修复率 | 缺陷修复率 | COUNT(本周已修复缺陷) / COUNT(本周新增缺陷) | >100% |
| 缺陷积压率 | 缺陷积压率 | COUNT(未修复缺陷) / COUNT(所有缺陷) | <10% |

#### 4. 缺陷时效

| 指标 | 说明 | 计算公式 | 目标值 |

## 📈 缺陷分析

### 分析方法

#### 1. 缺陷密度分析

**定义**：单位代码量的缺陷数量

**计算公式**：

```
缺陷密度 = 缺陷数量 / 代码行数（千行）
```

**示例**：

```
缺陷密度 = 100 / 100 = 1 缺陷/千行
```

**目标值**：< 2 缺陷/千行

#### 2. 缺陷分布分析

**定义**：缺陷在不同模块、功能、类型的分布情况

**分析方法**：

- 按模块分析：分析不同模块的缺陷分布
- 按功能分析：分析不同功能的缺陷分布
- 按类型分析：分析不同类型的缺陷分布
- 按严重级别分析：分析不同严重级别的缺陷分布

**示例**：

| 模块 | 缺陷数量 | 占比 |
|------|---------|------|
| 用户认证 | 20 | 20% |
| 日志管理 | 30 | 30% |
| 权限管理 | 15 | 15% |
| 备份管理 | 10 | 10% |
| 配置管理 | 25 | 25% |

#### 3. 缺陷趋势分析

**定义**：缺陷随时间的变化趋势

**分析方法**：

- 按周分析：分析每周的缺陷变化
- 按月分析：分析每月的缺陷变化
- 按版本分析：分析每个版本的缺陷变化

**示例**：

| 周次 | 新增缺陷 | 已修复缺陷 | 未修复缺陷 |
|------|---------|-----------|-----------|
| 第1周 | 20 | 15 | 5 |
| 第2周 | 15 | 20 | 0 |
| 第3周 | 10 | 12 | 0 |
| 第4周 | 5 | 8 | 0 |

#### 4. 缺陷根本原因分析

**定义**：分析缺陷的根本原因

**分析方法**：

- 鱼骨图分析：使用鱼骨图分析缺陷原因
- 5Why分析：使用5Why方法分析缺陷原因
- 帕累托分析：使用帕累托图分析缺陷原因

**示例**：

| 根本原因 | 缺陷数量 | 占比 |
|---------|---------|------|
| 需求不明确 | 30 | 30% |
| 设计缺陷 | 25 | 25% |
| 编码错误 | 20 | 20% |
