### 问题 #2: CI/CD 部署脚本配置错误 ⚠️ CRITICAL

**问题描述**:
1. 部署脚本引用不存在的 docker-compose 文件 (`docker-compose.${{ env }}.yml`)
2. 健康检查脚本不存在 (`tests/health_check.py`)
3. 环境变量 `env` 未定义
4. 无部署失败回滚机制

**解决方案**:

#### 2.1 修复环境检测

**文件**: `.github/workflows/ci-cd.yml`

```yaml
# 新增：设置部署环境变量步骤
- name: 设置部署环境
  id: deploy_env
  run: |
    if [[ "${{ github.ref }}" == "refs/heads/develop" ]]; then
      echo "env=development" >> $GITHUB_OUTPUT
      echo "compose_file=docker-compose.new.yml" >> $GITHUB_OUTPUT
    else
      echo "env=production" >> $GITHUB_OUTPUT
      echo "compose_file=docker-compose.yml" >> $GITHUB_OUTPUT
    fi
```

#### 2.2 修复部署流程

```yaml
- name: 部署到服务器
  uses: appleboy/ssh-action@master
  with:
    host: ${{ secrets[format('{0}_HOST', steps.deploy_env.outputs.env)] }}
    username: ${{ secrets[format('{0}_USERNAME', steps.deploy_env.outputs.env)] }}
    key: ${{ secrets[format('{0}_SSH_KEY', steps.deploy_env.outputs.env)] }}
    script: |
      cd /opt/yyc3-nas-ecs
      git pull origin ${{ github.ref_name }}

      # 使用正确的文件名
      docker-compose -f ${{ steps.deploy_env.outputs.compose_file }} pull
      docker-compose -f ${{ steps.deploy_env.outputs.compose_file }} up -d

      # 健康检查（带重试）
      MAX_RETRIES=30
      RETRY_COUNT=0
      while [ $RETRY_COUNT -lt $MAX_RETRIES ]; do
        if curl -f http://localhost:3000/api/v2/health > /dev/null 2>&1; then
          echo "✅ Health check passed!"
          break
        fi
        RETRY_COUNT=$((RETRY_COUNT + 1))
        sleep 2
      done

      # 运行数据库迁移
      docker-compose exec -T api python scripts/migrate.py upgrade
```

#### 2.3 添加回滚机制

```yaml
# 部署失败时的回滚
- name: 部署失败回滚
  if: failure()
  uses: appleboy/ssh-action@master
  with:
    host: ${{ secrets[format('{0}_HOST', steps.deploy_env.outputs.env)] }}
    username: ${{ secrets[format('{0}_USERNAME', steps.deploy_env.outputs.env)] }}
    key: ${{ secrets[format('{0}_SSH_KEY', steps.deploy_env.outputs.env)] }}
    script: |
      cd /opt/yyc3-nas-ecs
      git reset --hard HEAD~1
      docker-compose -f ${{ steps.deploy_env.outputs.compose_file }} up -d
```

**验收标准**:
- ✅ 部署脚本使用正确的 docker-compose 文件名
- ✅ 健康检查正确验证服务状态（最多重试 30 次）
- ✅ 部署失败时自动回滚到上一版本
- ✅ 数据库迁移自动执行

### 问题 #3: 健康检查端点缺失 ⚠️ CRITICAL

**问题描述**:
- 现有 `/api/v2/health` 端点仅返回固定响应
- 无实际服务状态检查
- 无法用于容器健康检查
- 无问题诊断信息

**解决方案**:

#### 3.1 增强健康检查端点

**文件**: `api/app/api/v2/__init__.py`

**新增检查项**:

1. **数据库连接检查**:
```python
try:
    result = db.session.execute(db.text('SELECT 1'))
    result.fetchone()
    health_status['checks']['database'] = {
        'status': 'healthy',
        'message': 'Database connection successful'
    }
except Exception as e:
    health_status['status'] = 'unhealthy'
    health_status['checks']['database'] = {
        'status': 'unhealthy',
        'message': f'Database connection failed: {str(e)}'
    }
```

2. **Redis 连接检查**:
```python
try:
    r = redis.from_url(redis_url, socket_connect_timeout=2, socket_timeout=2)
    r.ping()
    health_status['checks']['redis'] = {
        'status': 'healthy',
        'message': 'Redis connection successful'
    }
except Exception as e:
    # Redis 降级不影响整体状态
    health_status['checks']['redis'] = {
        'status': 'degraded',
        'message': f'Redis connection failed: {str(e)}'
    }
```

3. **磁盘空间检查**:
```python
disk_usage = shutil.disk_usage('/')
free_percent = (disk_usage.free / disk_usage.total) * 100

if free_percent < 10:
    health_status['status'] = 'unhealthy'
    disk_status = 'unhealthy'
elif free_percent < 20:
    disk_status = 'degraded'
else:
    disk_status = 'healthy'
```

4. **内存使用检查**:
```python
memory = psutil.virtual_memory()
memory_percent = memory.percent

if memory_percent > 90:
    health_status['status'] = 'unhealthy'
elif memory_percent > 80:
    health_status['status'] = 'degraded'
```

```json

  "version": "2.0.0",
  "timestamp": "2026-02-04T12:00:00.000Z",

    "database": {
```

**HTTP 状态码**:

## 🔧 P1 问题修复详情

### 问题: 环境配置验证不足

**问题描述**:
- 无 `.env.example` 文件指引
- 无环境变量验证
- 缺少必需变量时无法提前发现

**解决方案**:

#### 1.1 环境验证模块

**文件**: `api/config/env_validator.py`

**验证类别**:

1. **必需变量** (阻塞启动):
   - `DATABASE_URL`
   - `JWT_SECRET_KEY` (至少 32 字符)
   - `SECRET_KEY` (至少 32 字符)

2. **功能变量** (可选功能):
   - `REDIS_URL` - 缓存和会话
   - `SMTP_*` - 邮件发送
   - `OPENAI_API_KEY` - AI/LLM
   - `OLLAMA_API_URL` - 本地 LLM
   - `SENTRY_DSN` - 错误追踪

3. **推荐变量** (带默认值):
   - `NODE_ENV` - development/production/test
   - `LOG_LEVEL` - debug/info/warning/error
   - `CORS_ORIGINS` - 允许的跨域来源

#### 1.2 Flask 应用集成

**文件**: `api/app/__init__.py`

```python
def create_app(config_name=None):
    # ... 现有代码 ...

    # 生产环境：严格检查
    if config_name == 'production':
        from config.env_validator import validate_environment
        validate_environment(fail_on_error=True)
        logger.info("Environment validation passed")
    # 开发环境：宽松检查
    else:
        from config.env_validator import get_validation_report
        report = get_validation_report()

            logger.warning(f"Environment validation found {len(report.critical_errors)} issues")
```

**用法**:

- ✅ `.env.example` 已存在且完善
