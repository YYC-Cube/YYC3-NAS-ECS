### 阶段 2: Staging 环境测试 (1-2 天)

**目标**: 在独立 Staging 服务器验证完整功能

**步骤 A: 准备 Staging 服务器**

```bash
# 1. 登录 Staging 服务器
ssh user@staging-server

# 2. 创建项目目录
sudo mkdir -p /opt/yyc3-nas-ecs
sudo chown $USER:$USER /opt/yyc3-nas-ecs

# 3. 克隆代码（或使用现有代码）
cd /opt/yyc3-nas-ecs
git clone <repository-url> .

# 4. 配置环境
cp deploy/staging/.env.staging.template .env.staging
vi .env.staging  # 编辑配置

# 5. 验证环境变量
python -c "from config.env_validator import print_validation_report"
```

**步骤 B: 执行 Staging 部署**

```bash
# 1. 进入部署目录
cd /opt/yyc3-nas-ecs/deploy/staging

# 2. 执行部署
./deploy-staging.sh

# 3. 运行验证
./verify-staging.sh --full
```

**步骤 C: 功能验证**

| 功能 | 验证方法 | 预期结果 |
|------|----------|----------|
| 前端访问 | http://staging.yyc3.com | 页面正常加载 |
| 用户登录 | 注册/登录流程 | 功能正常 |
| API 端点 | curl /api/v2/health | 返回 200 |
| 数据库 | 读写操作 | 数据一致 |
| 监控 | Grafana 仪表盘 | 指标正常 |

**步骤 D: 压力测试**

```bash

# 预期结果:
# - 成功率: 100%
```

```bash

# 预期结果: 服务恢复到部署前状态
```

### 完整回滚 (5-10 分钟)

```bash
# 代码 + 数据库回滚
./rollback-production.sh --database

# 恢复到指定备份
./rollback-production.sh --backup-name production-backup-20260204-120000
```

### 回滚触发条件

满足以下任一条件立即回滚：
- ⚠️ API 健康检查失败持续 5 分钟
- ⚠️ 错误率超过 5%

- ⚠️ 数据库连接失败
- ⚠️ 发现严重安全漏洞
