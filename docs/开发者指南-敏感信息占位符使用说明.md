## 🎯 概述

为了确保项目代码安全，防止敏感信息泄露，YYC³ NAS-ECS 项目采用占位符机制来管理敏感配置信息。

### 核心原则

1. **永远不要将包含真实敏感信息的文件提交到 Git 仓库**
2. **使用 `.env.example` 文件作为配置模板**
3. **实际敏感信息存储在 `.env` 文件中（已在 `.gitignore` 中排除）**
4. **开发时使用占位符，部署时替换为实际值**

## 📁 配置文件说明

### 主配置文件

#### `.env` - 实际环境配置（不提交到 Git）
```bash
# 数据库配置
POSTGRES_USER=DB_USER_PLACEHOLDER
POSTGRES_PASSWORD=DB_PASSWORD_PLACEHOLDER
POSTGRES_DB=yyc3_nas

# API 配置
JWT_SECRET_KEY=JWT_SECRET_PLACEHOLDER
SESSION_SECRET=SESSION_SECRET_PLACEHOLDER

# 服务器配置
NAS_SERVER_IP=SERVER_IP_PLACEHOLDER
NAS_DOMAIN=DDNS_DOMAIN_PLACEHOLDER
```

#### `.env.example` - 配置模板（提交到 Git）
```bash
# 数据库配置
POSTGRES_USER=DB_USER_PLACEHOLDER
POSTGRES_PASSWORD=DB_PASSWORD_PLACEHOLDER
POSTGRES_DB=yyc3_nas

# API 配置
JWT_SECRET_KEY=JWT_SECRET_PLACEHOLDER
SESSION_SECRET=SESSION_SECRET_PLACEHOLDER

# 服务器配置
NAS_SERVER_IP=SERVER_IP_PLACEHOLDER
NAS_DOMAIN=DDNS_DOMAIN_PLACEHOLDER
```

#### `.env.development` - 开发环境配置
```bash
NODE_ENV=development
LOG_LEVEL=debug
DEBUG=true
```

#### `.env.production` - 生产环境配置
```bash
NODE_ENV=production
LOG_LEVEL=info
DEBUG=false
```

#### `.env.staging` - 预发布环境配置
```bash
NODE_ENV=staging
LOG_LEVEL=warn
DEBUG=false
```

### FRP 配置文件

#### `frpc.toml` - FRP 客户端配置
```toml
serverAddr = "SERVER_IP_PLACEHOLDER"
serverPort = 7001
auth.method = "token"
```

## 🔧 环境变量配置

### 步骤 1：创建实际配置文件

从模板创建实际配置文件：

```bash
# 复制示例配置文件
cp .env.example .env

# 编辑实际配置文件
vim .env
```

### 步骤 2：设置实际值

在 `.env` 文件中设置实际的敏感信息：

```bash
# 数据库配置（使用强密码）
POSTGRES_USER=your_db_user
POSTGRES_PASSWORD=your_strong_password_123
POSTGRES_DB=yyc3_nas

# JWT 配置（生成安全的随机密钥）
JWT_SECRET_KEY=$(openssl rand -base64 32)
SESSION_SECRET=$(openssl rand -base64 32)

# 服务器配置
NAS_SERVER_IP=8.152.195.33
NAS_DOMAIN=ddns.0379.email
```

### 步骤 3：验证配置

启动应用并验证配置是否正确：

```bash
# 启动开发服务器
npm run dev

# 或启动生产环境
npm run build
npm start
```

## 🔒 安全最佳实践

### 1. 密码安全

✅ **推荐做法**：
- 使用至少 16 位的强密码
- 包含大小写字母、数字和特殊字符
- 定期轮换密码（建议每 90 天）
- 使用密码管理器（如 1Password、Bitwarden）

❌ **避免做法**：
- 使用简单密码（如 `password123`）
- 在代码中硬编码密码
- 多个服务使用相同密码
- 在聊天工具中共享密码

### 2. 密钥安全

✅ **推荐做法**：
- 使用环境特定的密钥（开发/测试/生产）
- 使用密钥管理服务（如 AWS Secrets Manager、Azure Key Vault）
- 生成足够长度的密钥（至少 32 字符）
- 使用加密存储（如 HashiCorp Vault）

❌ **避免做法**：
- 在代码中硬编码密钥
- 将密钥提交到版本控制
- 在文档中记录实际密钥
- 在日志中输出密钥

### 3. 网络安全

✅ **推荐做法**：
- 使用 HTTPS 传输敏感信息
- 配置防火墙规则限制访问
- 使用 IP 白名单
- 定期审查访问日志

❌ **避免做法**：
- 在不安全的网络中传输敏感信息
- 暴露内部服务端口到公网
- 忽略安全更新和补丁

### 4. Git 安全

✅ **推荐做法**：
- 确保 `.env` 在 `.gitignore` 中
- 使用 `pre-commit` 钩子检查敏感信息
- 定期审查 Git 历史记录
- 使用 GitGuard 或类似工具扫描

❌ **避免做法**：
- 提交 `.env` 文件
- 提交包含密钥的配置文件
- 在公开仓库中保留测试密钥

## ❓ 常见问题

### Q1: 为什么使用占位符而不是实际值？

**A**: 使用占位符可以：
- 防止敏感信息泄露到公开仓库
- 让新开发者更容易了解需要配置什么
- 避免在代码中硬编码敏感信息
- 简化环境切换（开发/测试/生产）

### Q2: 如何生成安全的密钥？

**A**: 使用以下方法生成安全密钥：

```bash
# 使用 OpenSSL 生成随机密钥
openssl rand -base64 32

# 使用 Python 生成随机密钥
python3 -c "import secrets; print(secrets.token_urlsafe(32))"

# 使用 Node.js 生成随机密钥
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### Q3: .env 文件应该提交到 Git 吗？

**A**: **不应该！** `.env` 文件包含实际的敏感信息，应该：
- 添加到 `.gitignore`
- 只提交 `.env.example` 作为模板
- 使用环境变量在 CI/CD 中配置

### Q4: 如何在不同环境中使用不同配置？

**A**: 推荐以下方法：

1. **多环境配置文件**：
   ```
   .env.development   # 开发环境
   .env.staging       # 预发布环境
   .env.production    # 生产环境
   ```

2. **使用环境变量**：
   ```bash
   export NODE_ENV=production
   source .env.production
   ```

3. **使用配置管理工具**：
   ```bash
   # 使用 dotenv
   npm install dotenv-cli
   dotenv -e .env.production -- npm run build
   ```

### Q5: 如何在 CI/CD 中管理敏感信息？

**A**: 推荐以下方法：

1. **GitHub Actions Secrets**：
   ```yaml
   env:
     DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
     JWT_SECRET: ${{ secrets.JWT_SECRET }}
   ```

2. **环境变量注入**：
   ```yaml
   - name: Build
     run: |
       echo "DB_PASSWORD=${{ secrets.DB_PASSWORD }}" >> .env
       npm run build
   ```

3. **密钥管理服务**：
   ```yaml
   - name: Fetch Secrets
     uses: aws-actions/configure-aws-credentials
   ```

## 🚀 快速开始

### 新开发者快速开始

```bash

# 2. 创建实际配置文件

npm run dev
```

```bash
git pull origin main

# 2. 更新 .env 文件（如有新的占位符）
vim .env

# 3. 重启服务
npm run dev
```
